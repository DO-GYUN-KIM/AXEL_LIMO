## 1. `1_lane_track.pptx.pdf` — 딥 러닝 자율주행 (42쪽)

### 1-1. 한 줄 요약
카메라 이미지로 데이터를 모으고(`take_a_picture`), 외부 PC에서 목표 좌표를 클릭해 라벨을 만든 뒤(`img_lab2`), Colab에서 TensorFlow 회귀 모델(`dl_drive.h5`)을 학습합니다. 이 모델을 ONNX→TensorRT `.engine`으로 바꿔(`tf_to_trt`) `/control` 토픽으로 조향 오차를 내보내는 노드(`tf_track_detect` / `trt_track_detect`)까지 이어지는 전 과정입니다.

### 1-2. 핵심 내용
- 구조는 모듈식입니다. **주행 제어 = TensorFlow 모델**(조향 좌표 회귀)과 **인식 = YOLO 모델**(신호등·표지판·보행자 등)로 나눕니다.
- 진행 순서는 5단계입니다: 데이터 수집 → 라벨링 → 학습(Google Colab) → 최적화(Jetson TensorRT) → 자율주행 노드.
- 데이터 수집 시스템은 노드 3개로 구성됩니다: 카메라 센서 노드(orbbec_camera), 이미지 저장 노드(ROS2 서비스), 저장 요청(서비스 호출).
- 저장 용도는 2가지입니다.
  - **주행 판단용**: 300×300, `dataset/dl_images`
  - **객체 인식용**: 640×480 원본, `dataset/images/train`, `dataset/images/val`
- 저장 위치는 **`take_a_picture`를 실행한 터미널의 현재 경로를 기준**으로 정해집니다.
- 좌표 라벨링 도구 `img_lab2`는 **aarch64(LIMO의 Jetson)에서 실행할 수 없습니다.** 외부 PC에서 씁니다. Linux용 `image_labeler_linux.zip`(`img_lab2`)과 Windows용 `image_labeler_win.zip`(`img_lab2.exe`, python3.dll, python38.dll 포함)이 있습니다. 폴더는 `dataset/`, `images_labeled/`, `lib/`로 구성됩니다.
- 라벨링 모드는 2가지입니다. **"Normal"**(기본 주행)과 **"Turn"**(특수 상황, 예: 우회전 표지판). 이미지를 클릭하면 좌표가 **파일명**에 저장되고, 결과는 `/images_labeled` 폴더에 들어갑니다. 예시 파일명은 `17_17_10_20240411142624.jpg`입니다. 형식은 `x좌표1_x좌표2_?_타임스탬프`로 보입니다 **(추정, 세 번째 숫자의 뜻은 자료에 없음)**.
- 모델의 출력은 **tanh(-1~1) 범위의 x₁, x₂ 두 값**입니다. 출력 예시 화면으로 보면 x₁=Normal 모드 좌표, x₂=Turn 모드 좌표입니다.
- 최적화 결과는 `jtop`으로 확인합니다. 최적화 전 화면에서는 `tf_track_detect` 프로세스가 GPU 메모리 1.5G를 쓰고 GPU 사용률이 98.9%입니다. 최적화 후에는 84.5%로 떨어집니다. 두 화면 모두 `yolo_object_det`이 함께 돌고 있습니다.

### 1-5. 대회 미션에 쓰는 법
- **기본 차선 주행**: 대회 트랙에서 이미지를 새로 모으고 라벨링해 `dl_drive.h5`를 다시 학습하면 그대로 쓸 수 있습니다. `/control`의 normal_mode 값을 조향 오차로 씁니다.
- **M2 갈림길 A/B**: 이 모델은 출력이 **Normal/Turn 두 갈래 좌표**입니다. 표지판(YOLO)으로 A/B를 판단한 뒤 normal_mode와 turn_mode 중 하나를 고르는 방식이 바로 맞습니다. 대회 갈림길의 방향에 맞춰 "Turn" 라벨을 찍어야 합니다 **(추정)**.

## 3. `1_LiDAR 소개.pdf` — LiDAR (13쪽)

### 3-1. 한 줄 요약
YDLIDAR 드라이버를 띄워 `/scan`(LaserScan)을 확인하고 RViz로 시각화합니다. 이어서 전방 20cm×20cm 영역에 장애물이 있으면 `/e_stop`(Bool)을 True로 내는 예제 노드를 다룹니다.

### 3-2. 핵심 내용
- LIMO 전방에 **2D LiDAR**가 있습니다. 드라이버 로그에 나온 값은 Model: **Tmini Plus**, Scan Frequency **10Hz**, Sample Rate **4K**, Fixed Size 410입니다.
- `/scan` 실측값:
  - frame_id: `laser_link`
  - angle_min/max: **±1.9199 rad(±110°)**, angle_increment **0.01583 rad(약 0.91°)**, 약 243개 점 **(계산값)**
  - scan_time 0.1s, range_min 0.01m, range_max 64.0m
- `ranges`에 **0.0(무효값)**이 섞여 나옵니다(echo 첫 값). 필터링해야 합니다.
- RViz: Fixed Frame을 `laser_link`로 바꾸고, LaserScan의 Topic → Reliability Policy를 **Best Effort**로 바꿔야 보입니다. 드라이버가 sensor QoS로 퍼블리시하므로, 직접 만드는 구독자도 QoS를 맞춰야 할 수 있습니다 **(추정)**.
- 각도 0 rad는 로봇 정면(+x)이고, 반시계 방향이 +입니다(슬라이드 그림 기준).

### 3-3. 그대로 쓸 수 있는 명령어·토픽

| 항목 | 값 |
|---|---|
| 토픽 | `/scan` (`sensor_msgs/msg/LaserScan`) |

### 3-4. 코드 구조 (정답 코드 전체, 12쪽)
```python
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import LaserScan
from std_msgs.msg import Bool
import math

class ObstacleDetection(Node):
    def __init__(self):
        super().__init__('obstacle_detection_node')
        self.pub_ = self.create_publisher(Bool, '/e_stop', 10)
        self.sub_ = self.create_subscription(LaserScan, '/scan', self.laser_callback, 10)

    def laser_callback(self, msg: Bool):          # 원문 그대로. 타입 힌트는 LaserScan이 맞음(동작에는 영향 없음)
        obstacle_detect = Bool()
        obstacle_detect.data = False
        for i, distance in enumerate(msg.ranges):
            angle = msg.angle_min + i * msg.angle_increment
            x = distance * math.cos(angle)
            y = distance * math.sin(angle)
            if 0.01 < x < 0.2 and -0.1 < y < 0.1:
                obstacle_detect.data = True
                break
        self.pub_.publish(obstacle_detect)

def main(args=None):
    rclpy.init(args=args)
    obstacle_detection = ObstacleDetection()
    rclpy.spin(obstacle_detection)
    obstacle_detection.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```
- 알고리즘: 각 빔을 극좌표에서 직교좌표 (x, y)로 바꾼 뒤 직사각형 ROI 안에 점이 하나라도 있으면 True를 냅니다. 0.0 무효값은 x=0이 되어 `0.01 < x` 조건으로 자연히 걸러집니다.
- **불일치 주의**: 이 예제는 `/e_stop`을 퍼블리시하는데, YOLO 자료의 주행 제어 노드는 **`/emergency_stop`**을 구독합니다. 연결하려면 remap이 필요합니다(`--ros-args -r /e_stop:=/emergency_stop`) **(추정)**. 또는 WeGo 패키지 안에 따로 `/emergency_stop`을 내는 노드가 있는지 확인하십시오.
- 한 개의 점만으로 True가 되므로 노이즈에 약합니다. 점 개수 하한을 두는 것을 권합니다 **(추정)**.

### 3-5. 대회 미션에 쓰는 법
- **M7 3차선에 정차한 LIMO 회피**: x/y 직사각형 ROI 방식을 그대로 확장합니다. ① 내 차선 앞 ROI(예: x 0.0~0.6m, |y|<0.15m)에 점이 있으면 장애물로 판단 → ② 왼쪽과 오른쪽 차선 ROI 중 비어 있는 쪽 선택 → ③ 차선 변경 → ④ 지나간 뒤 복귀. 앞 단계(장애물 감지)만 자료에 있고, 차선 변경 상태기계와 복귀는 **직접 만들어야 합니다** (ROI 수치는 **추정**).
- **M8 라바콘**: 콘의 좌표를 (x, y)로 바꾸는 부분은 그대로 씁니다. 좌우 콘을 군집화해 두 줄의 중점을 따라가는 것(또는 가장 큰 빈 각도로 가는 것)은 자료에 없습니다. FOV ±110°이므로 옆에 있는 콘도 보입니다.
- **M4 T자 주차**: 뒤쪽은 FOV 밖입니다(±110°). 후진 주차할 때 뒤를 LiDAR로 볼 수 없으므로 옆 벽이나 콘과의 거리, 카메라 주차선, 오도메트리를 섞어야 합니다 **(추정)**.
- **비상 정지 전반**: `/e_stop` 예제를 안전장치로 항상 띄워 두는 것을 권합니다.

**03.Follow_color.py 알고리즘 (그대로 재사용할 수 있는 간단한 조향기)**
1. HSV 노랑 `lower1 [20,100,100]`, `upper1 [30,255,255]`로 `inRange` 후 이진화(0/1)
2. `histogram = np.sum(bin_img, axis=0)`(열 합), `histogram[histogram < 80] = 0`(노이즈 제거)
3. `nonzero_indices`의 첫 인덱스와 끝 인덱스 평균 = `avg_index`(못 찾으면 `center_x`)
4. `diff_index = center_x - avg_index`
5. 검출되면 `linear.x = 0.1`, 아니면 0.0. `angular.z = diff_index * pi / x`(x는 이미지 폭)
6. 이 방식은 "히스토그램 기반 차선 위치 찾기"로, sliding window의 첫 단계와 같습니다. **sliding window 자체는 자료에 없습니다.**

**detect_line.py (134줄, `DetectLine` 노드, 노드 이름 `detect_line`)**
- 구독: `/camera/color/image_raw` (**`Image`, 압축 아님**, `qos_profile_sensor_data`)
- 퍼블리시: `distance_y` (`std_msgs/Int32`), `debug_image` (`Image`, 0.1초 타이머)
- 파라미터 기본값:
  ```text
  roi_x_l: 0     roi_x_h: 320    roi_y_l: 400   roi_y_h: 480      # 640x480 중 왼쪽 아래 320x80
  lane_h_l: 0    lane_l_l: 90    lane_s_l: 100                     # (lane_s_l 줄은 일부가 가려져 있으나 100으로 읽힘)
  lane_h_h: 60   lane_l_h: 220   lane_s_h: 255                     # HLS 범위 (노란 차선)
  reference_distance: 170
  debug_image_num: 2      # 0: ROI, 1: Masking(mono8), 2: 원본에 기준선과 무게중심 표시
  ```
- 처리 순서: `imgmsg_to_cv2(bgr8)` → ROI 자르기 `[roi_y_l:roi_y_h, roi_x_l:roi_x_h]` → `cvtColor(BGR2HLS)` → `inRange(low, high)` → `cv2.moments` → `cx = m10/m00` → `distance_to_ref = reference_distance - cx`(차선이 없으면 0) → `distance_y` 퍼블리시
- 즉 **왼쪽 노란 중앙선을 x=170px에 맞추며 따라가는 방식**입니다. 차선을 못 찾으면 0을 내므로 "직진"으로 처리됩니다.
- 실제로 `/cmd_vel`로 바꾸는 제어 노드는 `track_application_launch.py` 안에 있을 것으로 보입니다. 그 코드는 자료에 없습니다 **(추정)**.

## 1. 2_ROS2_네트워크.pdf (15쪽)

### 1) 한 줄 요약 / 판정

### 2) 핵심 내용
- DDS: Master(roscore) 없이 노드가 서로 자동 발견(Discovery)합니다. 계층은 User Code → rclpy/rclcpp → rcl → rmw → DDS(Fast DDS 기본, Cyclone DDS로 교체 가능)입니다. (4~5쪽)
- ROS_DOMAIN_ID: 같은 번호끼리만 통신합니다. 기본값은 0이고, 실습 시 0~101 범위를 권장합니다. 용도는 "한 공유기에 여러 팀·로봇이 있을 때 통신 간섭 방지"입니다. (8쪽)
- 멀티 머신 통신 조건 (10쪽)
  - 조건 1: 같은 네트워크(동일 공유기)에 연결
  - 조건 2: 동일한 ROS_DOMAIN_ID
  - 두 조건이 맞으면 별도 설정 없이 자동 연결됩니다. 예로 원격 PC에서 로봇 토픽을 직접 echo·제어할 수 있습니다.
  - 확인 방법: ping → `ros2 topic list`
  - 주의: 다른 서브넷이거나 방화벽이 막으면 통신이 안 됩니다.
- QoS 3대 정책 (12~13쪽): Reliability(RELIABLE / BEST_EFFORT), Durability(VOLATILE / TRANSIENT_LOCAL), History(KEEP_LAST(N) / KEEP_ALL). Publisher와 Subscriber의 QoS가 호환되어야 통신이 성립합니다.
- **LiDAR QoS 예제 (14쪽)**: 퍼블리셔는 `LaserScan`을 `'scan'` 토픽에 BEST_EFFORT로 냅니다. 주석은 "센서 데이터용 QoS: BEST_EFFORT (실제 LiDAR 드라이버와 동일한 설정)"입니다. 구독자 주석은 "RELIABLE → 데이터 안 들어옴 (Pub은 BEST_EFFORT라서 호환 X) / BEST_EFFORT → 정상 수신"입니다.
  - 의미: LIMO의 `/scan`을 구독할 때 RELIABLE로 구독하면 아무것도 안 들어옵니다. BEST_EFFORT 또는 `qos_profile_sensor_data`를 써야 합니다(추정: LIMO 드라이버도 같은 설정이라는 자료 주석에 근거).

### 3) LIMO/대회 환경 특화 명령·설정 (자료 그대로)
```bash
# 설정 (터미널 또는 ~/.bashrc 에 추가)      (8쪽)
export ROS_DOMAIN_ID=30
```
10쪽 그림: `원격 PC  DOMAIN_ID=30` / `LIMO  DOMAIN_ID=30` / 공유기(Wi-Fi) / "같은 DOMAIN → 자동 연결".

14쪽 QoS 코드 핵심 줄:
```python
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy
from sensor_msgs.msg import LaserScan
from rclpy.qos import qos_profile_sensor_data

# 센서 데이터용 QoS: BEST_EFFORT (실제 LiDAR 드라이버와 동일한 설정)
qos = QoSProfile(
    reliability=ReliabilityPolicy.BEST_EFFORT,
    history=HistoryPolicy.KEEP_LAST,
    depth=10,
)
self.pub = self.create_publisher(LaserScan, 'scan', qos)

# (구독측)
# RELIABLE    → 데이터 안 들어옴 (Pub은 BEST_EFFORT라서 호환 X)
# BEST_EFFORT → 정상 수신
RELIABILITY = ReliabilityPolicy.BEST_EFFORT
self.sub = self.create_subscription(LaserScan, 'scan', self.callback, qos)
```
- 30은 예시 값입니다. 대회에서 쓸 번호는 자료에 없습니다. 대회 측 배정 여부를 확인해야 합니다(추정).

### 4) 원격 개발(노트북 ↔ 로봇) 절차 (자료에 있는 만큼)
1. 노트북과 LIMO를 같은 공유기(Wi-Fi)에 연결합니다.

5. 안 보이면 서브넷과 방화벽을 확인합니다.
