# LIMO Pro 자율주행 정석 로드맵 (단계별 체크포인트)

작성: 2026-11-04 · 일정과 상관없이 "정석대로 하면 이 순서"를 정리한 문서입니다.
각 단계는 **완료 기준**을 통과해야 다음 단계로 넘어갑니다. 앞 단계가 흔들리면 뒤 단계의 튜닝이 모두 다시 틀어지기 때문입니다.
`(추정)` 표시는 교육 자료나 공식 문서로 확인하지 못한 명령과 값입니다. 실제 이름은 차량에서 `ros2 pkg list`와 `ros2 launch <패키지> <Tab>`으로 확인하십시오.

## 0단계. 시작 전 준비
- [ ] 백업: `~/wego_ws/src` 전체, `conda env export -n dl_env > dl_env.yml`, `~/.bashrc`
- [ ] 측정 도구: 줄자, 마스킹 테이프, 체커보드(A4 이상, 칸 크기를 자로 실측), 수평계(스마트폰 앱 가능)

| 저장 공간 | `df -h /` | 남은 공간 20GB 이상 (녹화 파일용) |
| 상태 모니터 | `sudo pip3 install jetson-stats` 후 `jtop` | CPU·GPU·온도를 실시간으로 볼 수 있음 |

## 2단계. ROS2 환경
| 확인 | 명령 | 완료 기준 |
|---|---|---|

| 원격 연결 | 같은 공유기에서 노트북으로 `ros2 topic list` | 로봇 토픽이 노트북에 보임 |

## 3단계. LIMO 구동부
| 확인 | 방법 | 완료 기준 |
|---|---|---|
| 주행 모드 | 옆면 래치와 표시등 | 애커먼이면 초록색 |
| 베이스 드라이버 | `ros2 launch limo_base limo_base.launch.py` (추정, 패키지 이름 확인 필요) | `/cmd_vel` 구독, `/odom` 발행 |
| 수동 조작 | `ros2 launch wego teleop_launch.py` (교육 자료) 또는 `ros2 run teleop_twist_keyboard teleop_twist_keyboard` | 전진, 후진, 좌우 조향이 됨 |
| 토픽 주기 | `ros2 topic hz /odom` | 일정한 주기로 나옴 |
| 배터리 | 배터리 토픽 또는 상태 메시지(`ros2 topic list`에서 확인) | 전압이 보이고 기록됨 |
| **직진 거리 보정** | `/cmd_vel` 0.2m/s로 5초 → 줄자로 실제 거리 측정, `/odom` 값과 비교 | 오차 3% 이하. 크면 보정 계수를 기록 |
| **속도 정확도** | 0.1/0.2/0.3/0.4m/s 명령 → 실제 속도 측정 | 명령과 실제 속도 표 작성. 0.2m/s 이하 서행이 실제로 나오는지 확인 |
| **회전 보정** | 제자리(차동) 또는 최소 반경(애커먼)으로 360° → `/odom` yaw와 비교 | yaw 오차 5° 이하 |
| 최소 회전 반경 | 최대 조향으로 원 그리기 → 바닥에 표시 후 지름 측정 | 숫자 기록. 트랙 코너(안쪽 R600)와 주차 진입에 쓸 수 있는지 판단 |
| 정지 거리 | 0.3m/s에서 정지 명령 → 멈출 때까지 밀린 거리 | 숫자 기록. 정지선 ±5cm 맞출 때 보정값으로 씀 |
| 배터리 영향 | 완충일 때와 50%일 때 위 속도 측정 반복 | 차이 기록 |

## 4단계. 센서 기본 동작
**카메라 (Orbbec)**
- [ ] `ros2 launch orbbec_camera astra_stereo_u3.launch.py` → `ros2 topic hz /camera/color/image_raw/compressed`: 주기와 해상도 기록
- [ ] `ros2 topic echo /camera/color/camera_info --once`: 공장 보정값이 들어 있는지 확인
- [ ] **자동 노출과 자동 화이트밸런스를 끄고 고정값으로 설정** (드라이버 파라미터 이름은 `ros2 param list`로 확인). 자동으로 두면 조명이 바뀔 때마다 색 기준값이 흔들립니다.
- [ ] 장착 각도를 정하고 고정합니다. 이후 단계의 보정은 모두 이 각도 기준이므로 **이후에는 카메라를 건드리지 않습니다**(테이프나 나사로 고정).

**라이다 (YDLIDAR Tmini Plus)**
- [ ] `ros2 launch ydlidar_ros2_driver ydlidar.launch.py` → `ros2 topic hz /scan`: 약 10Hz
- [ ] 각도 방향: 상자를 차 **정면**, **왼쪽**, **오른쪽**에 차례로 놓고 RViz(Fixed frame `laser_link`, QoS Best Effort)에서 확인합니다. 정면이 0°인지, 왼쪽이 +인지 기록하고 `lidar_processor`의 `angle_offset_rad`, `flip_direction`에 반영합니다.
- [ ] 0.0 값과 차체에 맞은 점이 있는지 확인 → `range_min_m` 결정
- [ ] 라바콘과 정차 LIMO를 0.3/0.6/1.0m에 놓고 점이 몇 개 찍히는지 기록 (클러스터 기준값용)

## 5단계. 카메라 보정
**5-1. 내부 보정 (렌즈 왜곡), 체커보드 사용**
공장 보정값이 있어도 직접 한 번 하는 것이 정석입니다. 왜곡이 남아 있으면 버드아이에서 직선 차선이 휘어 보입니다.
```
sudo apt install ros-humble-camera-calibration
ros2 run camera_calibration cameracalibrator --size 8x6 --square 0.025 \
  --ros-args -r image:=/camera/color/image_raw -r camera:=/camera/color
```
- `--size`는 체커보드 **안쪽 교차점 수**(가로x세로)입니다. 칸 수가 아닙니다. `--square`는 칸 한 변을 실측한 길이(m)입니다.
- 압축되지 않은 `image_raw` 토픽이 필요합니다. 없으면 `ros2 run image_transport republish compressed raw ...`로 만듭니다.
- 화면 가장자리, 가까이, 멀리, 기울여서 X·Y·Size·Skew 막대가 모두 초록이 될 때까지 움직인 뒤 CALIBRATE → SAVE.
- **완료 기준**: 재투영 오차가 0.5px 이하 (도구에 표시됨). 결과 `ost.yaml`을 저장소 `config/`에 보관합니다.

**5-2. 바닥 투영 보정 (버드아이)** ← 대회에 가장 중요한 보정
- 체커보드를 **바닥에 평평하게**, 차 앞 정해진 위치(예: 앞바퀴에서 30cm 앞, 차 중심선에 맞춤)에 놓습니다.
- 사진 1장을 찍고 코너 4점의 화면 좌표와 실제 바닥 좌표(m)로 투영 변환(homography)을 계산합니다. 이 값을 `lane_detector`와 `parking_detector`의 `warp_src`, `meters_per_px_x/y`, `bottom_to_front_wheel_m`에 넣습니다.
- **완료 기준**: 버드아이 화면에서 직선 차선이 평행한 직선으로 보이고, 차선 폭이 화면 어디서나 0.55m로 계산됨. 바닥에 테이프로 30cm 간격 표시를 하고 버드아이에서 거리를 재서 오차 1cm 이내.

**5-3. 기구 치수 측정 (TF)**
- 줄자로 잽니다: 차 중심 → 카메라, 차 중심 → 라이다, 차 중심 → **앞바퀴 축**(판정 기준점), 차체 길이·폭, 네 모서리 위치(주차 판정).
- `static_transform_publisher`로 `base_link → camera_link`, `base_link → laser_link`를 등록하면 RViz에서 카메라와 라이다 데이터를 겹쳐 확인할 수 있습니다.

## 6단계. 트랙과 환경
- [ ] 주문 제작 트랙 치수를 도면과 비교합니다: 전체 10×6m, 차선 폭 550mm, 코너 R600/R650, 지그재그 구간 1677mm, 주차칸 크기.
- [ ] 시설물 배치: 신호등, 표지판(10cm 이상), 정차 LIMO 7대 + 주차장 양옆 2대, 라바콘, 방지턱(24mm 이하)
- [ ] 조명: 연습장 조명을 대회장과 최대한 비슷하게 맞추고, 시간대(낮과 밤)에 따라 색이 달라지는지 확인합니다. 바닥 반사가 심한 곳을 기록합니다.

## 7단계. 개발 기반
- [ ] AXEL_LIMO를 로봇 `~/axel_ws/src`에 clone하고 빌드합니다. 주최 `wego_ws`와 작업공간을 분리하고, 실행할 때 둘 다 source합니다.
- [ ] 녹화 파이프라인: `scripts/record_bag.sh`로 트랙 2바퀴를 녹화 → 노트북에서 `ros2 bag play`로 재생 → RViz와 rqt_image_view에서 확인
- [ ] 노트북 3대 모두 ROS2 Humble과 AXEL_LIMO가 빌드되는지 확인 (WSL2 가능)
- [ ] 브랜치 규칙과 차량 시간표 공유 (`역할분담_계획.md`)

## 8단계. 인식 개발
**차선 (A)**
- [ ] 녹화 데이터로 HSV(또는 HLS) 기준값을 맞춥니다. 시작값은 주최 `detect_line`의 low [0,90,100], high [60,220,255]입니다.
- [ ] 흰색과 노란색 차선을 구분할지 정합니다(트랙 색 확인).
- [ ] 정지선 검출: 정지선 앞 10~60cm 구간에서 거리 오차 2cm 이내.
- **완료 기준**: 녹화 전 구간에서 차선을 잃는 프레임이 5% 미만이고, 잃는 위치를 알고 있음(지그재그, 갈림길, 라바콘 구간은 예외 처리).

**YOLO (B)**
- [ ] 클래스 목록 확정 (최대 10개) → 촬영 → 라벨링 → RTX 3070 PC에서 학습 → Jetson에서 TensorRT 변환 → `yolo_object_detect` 실행 (`YOLO_학습_3070.md`)
- [ ] 표지판별로 반응할 거리를 bbox 면적으로 정합니다(차에서 거리별로 찍어 표로 만듦).
- **완료 기준**: 검증 사진 mAP50 0.9 이상, 차량에서 15fps 이상, 광고 모니터 화면에서 신호등을 잘못 검출하지 않음.

**라이다 (C)**
- [ ] 3차선 점유 판단, 콘 클러스터, 양옆 거리를 녹화 데이터에서 검증
- [ ] 트랙 밖 물체(사람, 벽) 거르기: 좌우 약 0.8m 밖 점은 제외
- **완료 기준**: 녹화 데이터에서 정차 LIMO 7대를 모두 올바른 차로로 판단.

## 9단계. 제어
- [ ] 직선 0.3m/s에서 차선 추종 PID 게인을 맞춥니다(먼저 P만, 흔들리면 D 추가).
- [ ] 코너(R600)에서 이탈하지 않는 최대 속도를 찾습니다.
- [ ] 속도별로 게인이 달라지면 0.15/0.3/0.4m/s 세 벌을 저장합니다.
- [ ] 정지선 정지: 3단계의 정지 거리를 반영해 ±5cm 안에 10회 중 9회 이상 멈춤.
- **완료 기준**: 0.3m/s로 무이탈 1바퀴를 연속 5회.

## 10단계. 미션 단위
미션마다 `start_mission:=<이름>`으로 그 미션부터 시작하며 하나씩 완성합니다. 배점과 난이도를 고려한 권장 순서입니다.
1. M6 지그재그(15), M5 서행(10): 기본 주행의 연장
2. M3 보행자(10), M1 신호등(15): 정지선 정지와 YOLO
3. M7 3차선(10), M8 라바콘(15): 라이다
4. M2 갈림길(10): 표지판을 무작위로 바꿔 가며 시험
5. M4 주차(15): 가장 마지막, 7점(부분 성공)부터
- **완료 기준**: 미션마다 단독 성공률 80% 이상, 15초 타임아웃에 걸리지 않음.

## 11단계. 통합과 리허설
- [ ] 전체 1바퀴를 연속 실행합니다. 미션이 실패해도 차가 멈추지 않고 다음 구간으로 넘어가는지 확인합니다.
- [ ] 리허설은 실전과 똑같이 합니다: 완충, 10분 제한, 2회 주행, 점수표(`tools/score_sheet.csv`) 기록.
- [ ] 실패 원인을 상위 3개만 골라 고칩니다. 새 기능은 넣지 않습니다.
- [ ] 코드 동결 후에는 설정값(YAML)만 바꿉니다. 바꿀 때마다 Git에 커밋합니다.
