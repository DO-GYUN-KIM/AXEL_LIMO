# rosbag 활용 안내 (LIMO Pro · AutoRace 2026 트랙 기준)

작성 2026-11-05. 대상: 팀 3명 전원. 녹화 스크립트는 `src/autorace_bringup/scripts/record_bag.sh`입니다.

## 0. 한 줄 요약

**차는 1대, 배터리는 1개입니다. 차로는 "녹화"와 "최종 확인"만 하고, 나머지 개발은 각자 노트북에서 녹화본(bag)을 재생하며 합니다.**
단, 재생은 "그때 찍힌 영상을 다시 보는 것"이라 **차선·YOLO·라이다 인식과 미션 전환 시점**은 bag으로 고칠 수 있지만,
**조향 세기·정지 위치처럼 차가 반응해야 결과가 나오는 것**은 bag으로 고칠 수 없습니다(그건 실차나 시뮬레이터에서).

## 1. rosbag이 무엇인지 (1분 설명)

- ROS2에서 오가는 메시지(카메라 사진, 라이다 거리, 주행 명령 등)를 **시간과 함께 그대로 파일에 저장**하는 기능입니다. 블랙박스와 같습니다.
- 재생하면 그 메시지들이 녹화 당시 순서·간격 그대로 다시 나옵니다. 우리 노드는 진짜 카메라인지 재생인지 구분하지 못하므로, 차 없이도 인식 코드를 돌려 볼 수 있습니다.
- 한 번 녹화한 bag은 세 사람이 동시에, 몇 번이든 씁니다. 같은 장면으로 수정 전/후를 비교할 수 있어 "고쳤더니 나아졌나"를 숫자로 판단할 수 있습니다.

## 2. 무엇을 녹화하나 (프로필 3가지)

| 프로필 | 명령 | 들어가는 토픽 | 언제 |
|---|---|---|---|
| `lap` (기본) | `record_bag.sh lap_slow` | 카메라(압축), `/scan`, `/odom`, `/imu`, `/limo_status`, `/limo/ack_cmd`, `/cmd_vel`, `/tf` | 매일 첫 녹화, 라이다·주차 구간 |
| `debug` | `record_bag.sh m1_red debug` | lap + 우리 노드 출력 `/autorace/*`, 주최 `/yolo_bounding_boxes` | 우리 코드를 켜고 달릴 때(리허설) |
| `yolo` | `record_bag.sh signs_AB yolo` | 카메라(압축)만 | YOLO 학습 사진 모으기 |

이번에 스크립트를 고친 이유:

- 예전 스크립트는 `/cmd_vel`만 녹화했습니다. 우리는 **애커먼 모드**라 차에 실제로 들어가는 명령은 `/limo/ack_cmd`입니다. 이게 없으면 "차가 왜 저렇게 꺾었나"를 bag에서 볼 수 없습니다.
- `/imu`를 추가했습니다. 방지턱(M5)을 넘을 때 차체가 흔들리는 모양이 IMU에 찍히므로, 방지턱 감지 보조 신호로 쓸 수 있는지 bag으로 먼저 볼 수 있습니다 **(아이디어, 미검증)**.
- 아직 나오지 않는 토픽을 목록에 넣어도 괜찮습니다. 그 토픽이 나오기 시작할 때부터 녹화됩니다.

**녹화하지 말 것:** `/camera/color/image_raw`(압축 안 된 원본), `/camera/depth/points`(점군). 압축본보다 수십 배 커서 Jetson 저장공간과 쓰기 속도를 금방 넘깁니다.

## 3. 트랙·미션별 녹화 계획

규정상 진행 순서: 출발 → M5 방지턱 → M6 지그재그 → M3 보행자 → M7 3차선 장애물 → M2 갈림길 → M8 라바콘 → M1 신호등 → M4 T자 주차.
**한 바퀴 통째로 1개 + 미션 구간별 짧은 bag 여러 개**로 나눠 찍으십시오. 짧은 bag이 다루기 쉽고, 재생할 때 원하는 장면을 바로 찾습니다.

| 구간 | 프로필 | 무엇을 찍나 | 이 bag으로 하는 일 | 담당 |
|---|---|---|---|---|
| 한 바퀴 | lap | 저속(0.2 m/s 안팎)으로 2바퀴. 차선 가운데·약간 치우친 상태 둘 다 | 차선 인식 임계값(HLS) 튜닝, 곡선에서 차선이 화면 밖으로 나가는지 | A |
| M5 방지턱 | lap | 서행 표지판 접근 ~ 방지턱 통과 | 표지판 인식 거리 확인, IMU 흔들림 확인 | A·B |
| M6 지그재그 | lap | 유도선 구간 3회 이상 | 유도선이 차선 인식을 흔드는지, 직전 방향 유지 로직 확인 | A |
| M3 보행자 | debug | 표지판 접근 ~ 정지선, 3회 | 표지판을 몇 m에서 처음 잡는지, 정지선 검출 시점 | A·B |
| M7 장애물 | lap | 장애물 배치를 바꿔 3가지 이상 | 라이다에 장애물이 어떻게 찍히는지, 차로 판단 | C |
| M2 갈림길 | yolo + debug | A 표지판, B 표지판 각각 따로. 거리·각도 다르게 | A/B 학습 사진, 투표(vote) 결정이 나오는 시점 | B |
| M8 라바콘 | lap | 콘 배치를 바꿔 3가지 이상 | 콘 간격 계산, 라이다 각도 범위(±110°인지 270°인지 실차 확인도 이걸로) | C |
| M1 신호등 | yolo + debug | 빨강→초록 바뀌는 순간 포함, 광고 모니터가 화면에 걸리는 장면 | 3색 학습 사진, 광고 모니터 오검출 사례 모으기 | B |
| M4 주차 | lap | 출발 위치를 바꿔 5회 이상, 양옆 LIMO 배치 포함 | 주차칸 인식(카메라), 양옆 거리(라이다) | C |

이름 규칙: 스크립트가 앞에 날짜·시각, 뒤에 프로필을 붙여 줍니다. 가운데 이름만 `미션_상황` 식으로 주십시오.
예: `20261106_093000_m2_signB_far_yolo`, `20261106_094500_m8_cones_layout2_lap`.

## 4. 녹화하는 방법 (실차)

```bash
# 차량(Jetson)에서. NoMachine 터미널 또는 SSH. tmux 안에서 실행하면 접속이 끊겨도 녹화가 계속됩니다.
df -h ~                                   # 남은 공간 먼저 확인
tmux new -s bag
bash ~/axel_ws/src/autorace_bringup/scripts/record_bag.sh lap_slow        # Ctrl+C로 끝
ros2 bag info ~/bags/<방금 폴더>          # 토픽별 메시지 수 확인. 카메라가 0개면 다시 찍기
```

- 녹화 직후 `ros2 bag info`로 **카메라·`/scan` 메시지 수가 0이 아닌지** 꼭 보십시오. 빈 bag을 들고 가서 저녁에 알게 되는 일이 가장 흔한 실수입니다.
- 조종기로 몰면 명령이 ROS를 거치지 않을 수 있어 `/limo/ack_cmd`·`/cmd_vel`이 비어 있을 수 있습니다. 그때 속도는 `/odom`으로 보십시오.
- 녹화 형식: 기본은 sqlite3입니다. `BAG_STORAGE=mcap`으로 바꾸면 Windows의 Foxglove·Lichtblick에서 바로 열기 편합니다(차량에 `ros-humble-rosbag2-storage-mcap` 설치 필요, 미설치 시 오류).
- 시간: 차량 시계가 틀리면 파일 이름 날짜가 틀어집니다. 첫날 `timedatectl`로 확인하십시오.

## 5. 재생해서 디버깅하는 방법 (노트북)

**먼저 안전 설정 (꼭):** 노트북의 `ROS_DOMAIN_ID`를 차량과 다른 번호로 두십시오(예: 차량 30, A 31, B 32, C 33).
같은 번호로 bag을 재생하면 bag 안의 `/limo/ack_cmd`가 공유기를 타고 **진짜 차에 전달되어 차가 움직일 수 있습니다.**
번호를 바꿀 수 없는 상황이면 재생할 때 `--remap /limo/ack_cmd:=/bag/ack_cmd /cmd_vel:=/bag/cmd_vel`을 붙이십시오.

```bash
# 터미널 1: 우리 노드만 띄움 (드라이버 없음, use_sim_time=true, 출력은 /autorace/cmd_vel_offline)
ros2 launch autorace_bringup offline.launch.py lane_debug:=true start_mission:=m1_traffic_light
# 터미널 2: 재생. --clock 필수 (없으면 노드 시간이 멈춰 타이머가 안 돕니다)
ros2 bag play ~/bags/20261106_101500_m1_red_debug --clock --rate 0.5
# 터미널 3: 확인
ros2 run rqt_image_view rqt_image_view /autorace/lane_debug/compressed
ros2 topic echo /autorace/mission_state
```

자주 쓰는 재생 옵션 (Humble 기준):

| 옵션 | 뜻 |
|---|---|
| `--rate 0.5` | 절반 속도로. 신호등 색이 바뀌는 순간처럼 빠른 장면 볼 때 |
| `--start-offset 30` | 30초 지점부터 |
| `--loop` | 끝나면 처음부터 반복. 임계값 바꿔 가며 볼 때 |
| `--topics /camera/color/image_raw/compressed /scan` | 이 토픽만 재생 |
| 재생 중 스페이스바 | 일시정지 / 다시 재생 |

### 담당별 디버깅 예

- **A 차선:** 한 바퀴 bag을 `--loop`로 틀어 두고 `params.yaml`의 차선 임계값을 바꿔 가며 `/autorace/lane_debug/compressed`를 봅니다. 곡선·유도선(M6)·횡단보도에서 차선을 놓치는 프레임을 찾는 것이 목적입니다.
- **B YOLO:** M1·M2·M3 bag을 재생하며 `/autorace/detections`를 봅니다. "몇 m에서 처음 잡히나", "광고 모니터를 신호등으로 착각하나"를 확인하고, 틀린 장면은 5장의 방법으로 사진을 뽑아 재학습에 넣습니다.
- **C 라이다:** M7·M8·M4 bag을 RViz로 열어 `/scan`을 보고(Fixed Frame은 `/scan`의 frame_id), `/autorace/lidar_info`가 장애물·콘을 맞게 잡는지 봅니다. 라이다 실제 각도 범위도 여기서 확정합니다.
- **미션 전환(통합):** debug 프로필로 찍은 한 바퀴 bag을 `start_mission:=start`로 재생하며 `/autorace/mission_state`가 순서대로 넘어가는지 봅니다. 앞서 지적된 약점(신호를 놓치면 시간 초과로 다음 미션이 밀리는 문제)을 차 없이 재현할 수 있습니다.
- **비교:** `rqt_plot`에 녹화 당시 명령과 `/autorace/cmd_vel_offline`을 같이 띄우면 "지금 코드라면 그 장면에서 어떻게 움직였을지"를 볼 수 있습니다.

### bag으로 못 하는 것

bag 속 차는 우리 새 명령에 반응하지 않습니다. 그래서 **조향 이득(얼마나 세게 꺾나), 정지선 ±5 cm 정지, 주차 궤적, 차로 변경 타이밍**은 bag 결과를 믿으면 안 됩니다.
이런 건 bag으로 인식이 맞는지만 확인한 뒤 실차(또는 Isaac Sim/Gazebo)에서 맞춥니다.

## 6. YOLO 학습 사진 모으기

```bash
python3 tools/extract_frames.py ~/bags/20261106_093000_m2_signB_far_yolo --every 10 --out ~/yolo/ours/1106_signB
# 특정 구간만:  --start 12 --end 25   (bag 시작 후 초)
# mcap으로 찍었다면: --storage mcap
```

- `--every 10`은 10장 중 1장입니다. 카메라가 30장/초라면 초당 3장이 나옵니다(카메라 속도는 `ros2 topic hz`로 확인, 미확인).
- 비슷한 사진만 많으면 효과가 없습니다. **거리(가까이·멀리), 각도(정면·비스듬히), 조명(창가·형광등), 일부 가려짐**을 일부러 섞어 찍으십시오.
- 오검출을 막으려면 **아무것도 없는 장면(광고 모니터, 빈 트랙)**도 빈 라벨로 넣습니다. 이후 `tools/prepare_dataset.py`로 합치고 train/val을 나눕니다(자세한 순서는 `YOLO_준비_안내서.md`).
- 대회장 조명은 학교와 다릅니다. **11/18(대회 첫날) 연습 시간이 있으면 yolo 프로필로 꼭 녹화**해 두십시오. 1차(11/19)와 2차(11/20) 사이에 재학습할 근거가 됩니다(연습 시간 유무는 미확인).

## 7. 용량·성능 주의점

| 항목 | 대략값 (추정, 실측 필요) |
|---|---|
| 압축 카메라 640×480, 30장/초 | 1분에 약 60~110 MB |
| 압축 안 된 카메라 | 1분에 약 1.6 GB (녹화 금지) |
| `/scan` 등 나머지 | 1분에 수 MB 이하 |
| 한 바퀴(2~3분) lap bag | 약 200~350 MB |

- 실제 값은 녹화 전 `ros2 topic bw /camera/color/image_raw/compressed`로 재십시오.
- Jetson 저장공간은 모델·이미지 크기에 따라 다릅니다(미확인). **매일 끝날 때 노트북으로 옮기고 차량에서는 지우는 것**을 규칙으로 하십시오. 꽉 차면 녹화가 멈추거나 다른 프로그램이 오류를 냅니다.
  옮기기: `scp -r <차량>:~/bags/20261106_* D:\도균\AutoRace\bags\` (유선 또는 5 GHz 권장)
- **압축 옵션은 권하지 않습니다.** 카메라는 이미 JPEG라 더 줄지 않고, Jetson CPU만 씁니다.
- 녹화도 CPU·디스크를 씁니다. 리허설 때 녹화를 켠 채로 한 번, 끈 채로 한 번 달려 차선 처리 속도(`ros2 topic hz /autorace/lane_info`)가 떨어지는지 보십시오. 떨어지면 대회 주행에서는 `yolo`처럼 가벼운 프로필만 쓰거나 끕니다.
- 경기 주행 중 녹화가 허용되는지는 규정에 없습니다(미확인). 허용되면 1차 경기 bag이 2차 전 수정의 가장 좋은 근거입니다.
- bag은 Git에 올리지 않습니다(`.gitignore`). 팀 공유 드라이브에 올리고, `tools/score_sheet.csv`의 `bag_name` 칸에 이름을 적어 어떤 코드(`git_commit`)·배터리로 찍었는지 남깁니다.

## 8. 하루 사용 순서 (권장)

1. 차량 켜기 → `df -h ~` → 드라이버 기동(`ros2 launch wego teleop_launch.py` 등) → `ros2 topic list`로 카메라·`/scan`·`/limo/ack_cmd` 확인
2. **녹화 30분:** 한 바퀴 lap 1개 + 그날 담당자가 필요한 미션 구간 bag 몇 개
3. `ros2 bag info`로 확인 → 노트북으로 복사 → 공유 드라이브
4. 각자 노트북에서 재생하며 수정 → 수정본은 차량 시간에 실차 확인(이때 debug 프로필로 녹화)
5. 리허설 결과는 score_sheet.csv에 bag 이름과 함께 기록
