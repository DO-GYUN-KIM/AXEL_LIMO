## 0. 결론: 권장 구성 한 장

| 층 | 권장 | 쓰는 이유 |
|---|---|---|
| 네트워크 | **팀 전용 공유기 1대** (대회장에도 가져감) + 차량 IP 고정(DHCP 예약) | 학교·대회장 어디서든 같은 IP·같은 설정. 대회장 와이파이가 없어도 동작 |
| 명령·코드 | **SSH** (키 인증) + **VS Code Remote-SSH** + **tmux** | 가볍고, 끊겨도 실행 중인 노드·녹화가 죽지 않음. Claude가 바로 다룰 수 있음 |
| 화면이 필요할 때 | **NoMachine** (이미 설치됨, 위키 기준) | RustDesk보다 나은 점은 없지만 이미 깔려 있어 설치·설정이 0 |
| 토픽 보기(rviz 대신) | **foxglove_bridge**(차량) + **Foxglove 또는 Lichtblick**(Windows 노트북) | Windows에서 ROS 설치 없이 카메라·라이다·토픽 그래프를 봄. DDS를 와이파이로 넘기지 않음 |
| 코드 흐름 | GitHub `main` = 차에서 돌아가는 코드. 기능 브랜치 → PR → `main`. 차량은 `tools/car_deploy.sh`로만 배포 | 누가 무엇을 올렸는지 기록이 남고, 롤백이 한 줄 |
| Claude | **연습 중: Jetson에 Claude Code 설치 + tmux + Remote Control**, **대회장: 노트북 Claude Code가 SSH로 차량 조작** | 차에서 `ros2 topic echo`·로그를 Claude가 직접 봄. 대회장은 차량에 인터넷이 없으므로 노트북(휴대폰 테더링)으로 넘김 |
| 안전 | 조종기 SWB는 항상 사람 손에. Claude 권한 설정으로 주행 명령 발행은 금지·확인 요청 | 권한 설정은 보조 장치일 뿐이고, 진짜 정지 수단은 조종기 |

이 구성을 고른 핵심 근거 세 가지입니다.

1. **대회장 와이파이를 못 쓸 수 있습니다.** 그래서 공유기를 직접 가져가고, 차량 배포가 인터넷 없이도 되도록 했습니다(5장 "오프라인 배포").
2. **팀 노트북이 Windows입니다.** Windows에서 rviz를 쓰려면 WSL2에서 DDS 멀티캐스트를 와이파이 너머로 받아야 해서 자주 막힙니다. Foxglove 방식은 차량이 웹소켓(포트 8765) 하나만 열면 끝납니다.
3. **차 1대를 3명이 씁니다.** 배포를 스크립트 하나로 몰아 잠금과 기록을 남기게 했습니다.

> 기존 문서와 다른 점: `로드맵_정석.md`·`교육자료_정리.md`는 "`ROS_LOCALHOST_ONLY=1` 줄을 지우고 노트북에서 `ros2 topic list`"를 권했습니다. 이 구성에서는 노트북이 DDS로 직접 붙지 않으므로 **그 줄을 남겨도 됩니다(오히려 다른 팀과의 간섭을 막습니다)**. 노트북 rviz를 꼭 써야 할 때만 지우십시오. 아래 3장에서 둘 중 하나로 정합니다.

## 1. 원격 접속 도구 비교

### 1-1. 원격 데스크톱

| 항목 | NoMachine | RustDesk | VNC(x11vnc 등) |
|---|---|---|---|
| 차량에 설치 | **이미 설치됨**(위키) | 새로 설치(arm64 패키지 있음 **(추정)**) | 새로 설치 |
| 같은 공유기에서 | 목록에 자동 표시, 빠름 | IP 직접 연결 가능 | 됨, 느림 |
| 인터넷 너머(집에서) | 포트 개방 또는 VPN 필요 | 공개 중계 서버로 바로 됨(지연 큼) | VPN 필요 |
| 모니터 없이(헤드리스) | 가상 화면 또는 HDMI 더미 플러그가 필요할 수 있음 **(추정)** | 같음 | 같음 |
| Jetson 부하 | 화면 인코딩만큼 CPU·GPU 사용 | 비슷 | 비슷 |
| Claude와 연동 | 없음 (사람용) | 없음 | 없음 |

**판단:** 원격 데스크톱은 "사람이 GUI를 볼 때"만 씁니다. NoMachine이 이미 있으므로 RustDesk를 추가할 이유가 없습니다. 집에서 접속은 RustDesk 중계 대신 아래 Tailscale + SSH로 해결합니다. **실제 채점 주행 중에는 원격 데스크톱을 끕니다**(화면 인코딩이 YOLO·카메라와 자원을 나눠 씀).

### 1-2. SSH (주 경로)

- 장점: 가장 가볍고, 끊겨도 tmux 안 작업은 살아 있습니다. VS Code Remote-SSH로 차량의 파일을 노트북에서 바로 편집합니다. Claude Code가 그대로 다룰 수 있는 유일한 경로입니다.
- 위키에는 SSH 안내가 없습니다. `openssh-server` 설치 여부는 3장 1단계에서 확인합니다.
- **보안:** 기본 계정 `wego/wego`는 대회장 같은 공유 네트워크에서 누구나 들어올 수 있는 상태입니다. 키 인증으로 바꾸고 비밀번호 로그인을 끕니다(3장 3단계). 팀 공유기를 쓰면 위험이 크게 줄지만, 비밀번호 변경은 그래도 합니다.

### 1-3. 집·다른 건물에서 접속 (선택)

- **Tailscale**(무료 개인 플랜): 차량과 노트북에 설치하면 인터넷만 있으면 어디서든 `ssh wego@axel-limo`가 됩니다. 포트 개방이 필요 없습니다.
- 차량이 켜져 있고 인터넷에 붙어 있을 때만 의미가 있으므로 **선택 사항**입니다. 대부분의 개발은 rosbag으로 각자 노트북에서 합니다.

### 1-4. 토픽 시각화

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| NoMachine 안에서 rviz2 | 설정 0 | Jetson에서 rviz 렌더링 + 화면 전송 = 무거움 | 급할 때만 |
| 노트북 rviz2 (WSL2/우분투, DDS 직접) | 익숙함 | `ROS_LOCALHOST_ONLY` 제거, 같은 `ROS_DOMAIN_ID`, 와이파이 멀티캐스트, WSL2 네트워크 설정이 모두 맞아야 함. 이미지 토픽이 와이파이를 꽉 채움 | 우분투 노트북이 있을 때만 |
| **foxglove_bridge + Foxglove/Lichtblick** | Windows 앱·브라우저에서 바로. 필요한 토픽만 구독. `.mcap` 녹화 파일도 같은 앱으로 재생 | 차량에 패키지 1개 설치. Foxglove 앱은 계정 필요(무료 범위 확인 필요 **(추정)**). 계정을 피하려면 오픈소스 Lichtblick | **권장** |

## 2. Claude를 어디에 둘 것인가

| 방식 | 장점 | 단점 |
|---|---|---|
| A. **Jetson에 Claude Code 직접 설치** | `ros2 topic echo`, `ros2 node info`, 빌드 오류, 로그를 Claude가 직접 읽고 고침. `claude remote-control`을 켜 두면 휴대폰·claude.ai에서 차량 작업을 이어서 지시 | 차량이 인터넷에 붙어 있어야 함(대회장 불가 가능성). 차량에 한 사람의 Claude 계정이 로그인됨(팀원이 쓰면 그 계정 사용량). 실행 중 메모리 수백 MB **(추정)** |
| B. 노트북 Claude Code + SSH | 각자 자기 계정. 노트북에 인터넷(휴대폰 테더링)만 있으면 됨 → 대회장에서도 됨 | 명령마다 `ssh limo '...'` 형태. ROS 환경을 매번 불러와야 함(아래 `limo` 래퍼로 해결) |
| C. 클라우드 Claude (이 프로젝트) | 문서·코드 작성, PR, 리뷰를 GitHub로 처리. 차량을 직접 못 만짐 | 실차 디버깅 불가 |

**권장 분담**

- **코드 작성·리뷰·PR**: C(이 프로젝트) 또는 각자 노트북의 Claude Code. 결과는 GitHub 브랜치로.
- **실차 디버깅(학교 연습)**: A. 차량 tmux 안에서 Claude Code를 띄우고 `claude remote-control`로 휴대폰/노트북에서 지시합니다. 차 옆에서 조종기를 든 사람이 지시자입니다.
- **대회장**: B. 노트북은 공유기(차량 LAN)와 휴대폰 USB 테더링(인터넷)에 동시에 붙습니다.

**Claude 안전 규칙** (저장소 `.claude/settings.json`에 넣어 두었습니다)

- 금지: `ros2 topic pub /limo/ack_cmd`, `ros2 topic pub /cmd_vel`, 강제 push, `~/wego_ws` 삭제, `apt upgrade`(JetPack·드라이버 깨짐 방지).
- 확인 요청: `ros2 launch`, `ros2 run`, 그 밖의 `ros2 topic pub`, `sudo`, `git push`, 배포 스크립트.
- 자동 허용: 읽기 전용 ROS 명령(`topic list/echo/hz/info`, `node list/info`, `param get/list`, `bag info`), `colcon build`, `git status/diff/log/fetch`.
- **한계:** 권한 설정은 "그 명령어 문자열"만 막습니다. Claude가 파이썬 스크립트를 만들어 주행 명령을 낼 수도 있으므로, **차가 움직일 수 있는 상태에서는 반드시 사람이 조종기를 들고 SWB로 즉시 끊을 수 있어야 합니다.** 바퀴를 띄운 받침대 위에서 먼저 시험하는 것을 기본으로 합니다.

## 3. 설정 순서 (한 번만, 약 2~3시간)

담당: A(팀장)가 차량, 각자 자기 노트북. 각 단계 끝의 "확인"이 되면 다음으로 넘어갑니다.

### 1단계. 차량 기본 확인 (NoMachine 또는 모니터·키보드)

```bash
lsb_release -a; cat /etc/nv_tegra_release      # Ubuntu 22.04, JetPack 버전
ip -br addr                                    # wlan IP, 유선(eth) 포트가 있는지
grep -n -E "LOCALHOST|DOMAIN|RMW" ~/.bashrc    # ROS 네트워크 설정 현재값
systemctl status ssh || sudo apt install -y openssh-server
df -h ~                                        # rosbag 저장 여유 공간
```
확인: SSH 서비스가 `active (running)`. 결과를 팀 채팅에 붙여 둡니다.

### 2단계. 팀 전용 공유기

1. 공유기(ipTIME 등 가정용이면 충분) SSID 예: `AXEL_LAB`, 5 GHz 우선 **(차량 무선 칩이 5 GHz를 지원하는지 1단계에서 확인, 추정)**.
2. 관리 화면에서 차량 MAC에 **IP 예약**: 예) `192.168.0.50`.
3. 학교: 공유기 WAN 포트에 학교 유선 인터넷을 꽂으면 차량도 인터넷 사용(Claude Code, git, apt). 유선이 없으면 노트북만 휴대폰 테더링.
4. 대회장: WAN 없이 LAN만 씁니다. 차량 배포는 5장 오프라인 방식.
5. 차량을 공유기에 연결: `sudo nmcli dev wifi connect AXEL_LAB password '<비번>'` (자동 재연결은 기본값). 학교 와이파이 연결은 남겨 두되 우선순위를 낮춥니다: `nmcli con mod AXEL_LAB connection.autoconnect-priority 10`.

확인: 차량 재부팅 후 노트북에서 `ping 192.168.0.50`.

### 3단계. SSH 키와 보안 (각자 노트북, Windows PowerShell)

```powershell
ssh-keygen -t ed25519 -C "<이름>-laptop"         # 엔터 3번
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh wego@192.168.0.50 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
`C:\Users\<사용자>\.ssh\config`에 추가:
```
Host limo
    HostName 192.168.0.50
    User wego
    ServerAliveInterval 15
```
3명 키를 모두 넣은 뒤 차량에서:
```bash
passwd                                           # wego 비밀번호 변경 (팀 비밀 채널로만 공유)
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh
```
주의: 비밀번호 로그인을 끄기 전에 3명 모두 `ssh limo`가 되는지 확인합니다. NoMachine은 새 비밀번호로 접속합니다.
확인: `ssh limo` 가 비밀번호 없이 열림.

### 4단계. 차량 작업 공간 (저장소 = 작업 공간)

저장소 최상위에 `src/`가 있으므로 저장소를 그대로 작업 공간으로 받습니다. 주최 측 `~/wego_ws`는 **건드리지 않고** 그 위에 겹쳐 씁니다(overlay).

GitHub 인증은 차량 전용 **Deploy key**(저장소 설정 → Deploy keys)를 씁니다. 개인 계정 토큰을 차량에 두지 않기 위해서입니다.
```bash
ssh-keygen -t ed25519 -C "axel-limo" -f ~/.ssh/id_github -N ""
cat ~/.ssh/id_github.pub        # → GitHub 저장소 Settings → Deploy keys → Add (Allow write access 체크: 튜닝 브랜치 push용)
cat >> ~/.ssh/config <<'EOF'
Host github.com
    IdentityFile ~/.ssh/id_github
EOF
git clone git@github.com:DO-GYUN-KIM/AXEL_LIMO.git ~/axel_ws
git -C ~/axel_ws config user.name "axel-limo"; git -C ~/axel_ws config user.email "axel-limo@local"
sudo apt install -y tmux ros-humble-foxglove-bridge
```
`~/.bashrc` 끝에 (순서 중요):
```bash
source /opt/ros/humble/setup.bash
source ~/wego_ws/install/setup.bash
[ -f ~/axel_ws/install/setup.bash ] && source ~/axel_ws/install/setup.bash
export ROS_DOMAIN_ID=<팀 번호>      # 대회장에서 다른 팀과 겹치지 않는 번호
```
확인: `bash ~/axel_ws/tools/car_deploy.sh 도균 main` 이 빌드까지 성공.

### 5단계. 시각화 (노트북 rviz 방식과 둘 중 하나)

- 차량: `ros2 launch foxglove_bridge foxglove_bridge_launch.xml` (tmux 창 하나에서)
- 노트북: Foxglove(또는 Lichtblick) → Open connection → Foxglove WebSocket → `ws://192.168.0.50:8765`
- 레이아웃: Image(`/camera/color/image_raw/compressed`), 3D(`/scan`), Plot(`/limo/ack_cmd` 조향·속도), Raw(`/autorace/mission_state`). 레이아웃 파일을 저장소 `tools/`에 커밋해 3명이 같은 화면을 씁니다.
- 이 방식이면 `ROS_LOCALHOST_ONLY=1`을 남겨도 됩니다(브리지가 차량 안에서 구독).

확인: 노트북에서 카메라 영상과 라이다 점이 보임.

### 6단계. Claude Code (차량)

```bash
curl -fsSL https://claude.ai/install.sh | bash     # Linux arm64 지원
cd ~/axel_ws && tmux new -s claude
claude                                             # 처음 한 번 로그인 (도균 계정)
# 휴대폰·노트북에서 이어서 지시하려면 tmux 안에서:
claude remote-control
```
- 저장소의 `.claude/settings.json` 권한 규칙이 자동 적용됩니다.
- 저장소에 `CLAUDE.md`(차량 토픽 이름, 애커먼 `/limo/ack_cmd`만 받음, 배포 스크립트 사용법)를 두면 Claude가 매번 설명 없이 시작합니다. 첫 실차 확인 후 작성을 권합니다.

### 7단계. 노트북 래퍼 (방식 B, 대회장 대비)

노트북 Claude Code가 ROS 명령을 한 줄로 실행하도록, 차량 `~/.bashrc`의 ROS 설정을 불러오는 래퍼를 씁니다.
```bash
ssh limo 'bash -lic "ros2 topic hz /scan"'
```
Claude Code에는 "차량 명령은 `ssh limo 'bash -lic \"...\"'` 형태로 실행"이라고 `CLAUDE.md`에 적어 둡니다.

## 4. tmux 운영 (끊겨도 살아 있게)

차량에서 사람·Claude 모두 tmux 세션 이름을 고정해 씁니다.

| 세션 | 내용 |
|---|---|
| `drv` | `ros2 launch wego teleop_launch.py` (드라이버, 카메라, 라이다) **(실제 기동 명령은 첫 실차에서 확인)** |
| `app` | `ros2 launch autorace_bringup robot.launch.py` |
| `bag` | `bash ~/axel_ws/src/autorace_bringup/scripts/record_bag.sh <이름>` |
| `viz` | foxglove_bridge |
| `claude` | Claude Code |

## 5. GitHub 흐름

### 5-1. 브랜치

- `main`: **차에서 돌아가는 것이 확인된 코드만.** 직접 push 금지(PR로만).
- 기능 브랜치: `feat/lane`(A), `feat/yolo`(B), `feat/lidar-parking`(C)처럼 역할별. 하루 1번 이상 `main`을 받아 합칩니다.
- 차량 튜닝 브랜치: `tune/<월일>-<이름>` (차량에서 파라미터를 바꾼 기록, 스크립트가 안내).
- 태그: 동결 시 `v-freeze`(11/17 저녁), 대회 당일 바꾸면 `v-day1`, `v-day2`. 문제가 생기면 이전 태그로 즉시 롤백.

GitHub 저장소 설정: Settings → Branches에서 `main` 보호(PR 필수)를 켭니다. 비공개 저장소의 브랜치 보호는 GitHub Pro(학생 혜택 포함)가 필요할 수 있습니다 **(추정)**. 안 되면 "main 직접 push 금지"를 팀 규칙으로만 둡니다.

### 5-2. 배포 (학교, 인터넷 있음)

```
노트북: git push origin feat/lane  →  (차량) bash tools/car_deploy.sh 도균 feat/lane  →  주행 시험
       →  잘 되면 PR → main 병합  →  (차량) bash tools/car_deploy.sh 도균 main
```
`car_deploy.sh`가 하는 일: 잠금 확인 → 차량에서 고친 파일이 남아 있으면 중단 → `git fetch` → 해당 커밋으로 체크아웃 → `colcon build --symlink-install` → `~/axel_ws/DEPLOYED`에 "시각 | 이름 | 브랜치 | 커밋" 기록.
- `--symlink-install`이라 `config/*.yaml`만 바꾼 경우 재빌드 없이 노드만 재시작하면 됩니다.
- 지금 차에 무엇이 올라가 있는지: `bash tools/car_deploy.sh --status`.

### 5-3. 오프라인 배포 (대회장, 인터넷 없음)

차량을 노트북의 git 원격으로 추가해 공유기 LAN으로 바로 밀어 넣습니다.
```powershell
git remote add car limo:axel_ws        # 한 번만 (ssh config의 limo 별칭 사용)
git push car feat/fix-light            # 차량 저장소에 브랜치 생성
ssh limo "bash ~/axel_ws/tools/car_deploy.sh 도균 feat/fix-light"
```
스크립트는 `git fetch`가 15초 안에 실패하면 오프라인으로 보고 로컬 브랜치를 씁니다. 체크아웃을 detach로 하므로 `git push car`가 "현재 브랜치라 거부" 오류 없이 들어갑니다. 인터넷이 돌아오면 노트북에서 `git push origin`으로 GitHub에도 남깁니다.

**대회 전 준비:** 대회장에는 인터넷이 없을 수 있으므로 `pip`·`apt` 의존성(ultralytics 등), YOLO 가중치(`.pt`/`.engine`, Git 제외 파일)를 11/17까지 차량에 모두 설치·복사해 둡니다. 가중치는 `scp best.engine limo:~/axel_ws/models/`.

## 6. 3명이 차 1대를 쓰는 규칙

1. **차 사용자는 한 번에 1명.** `car_deploy.sh <이름>`이 잠금을 겁니다. 끝나면 `--release <이름>`. 팀 채팅에 "차 씀 / 차 놓음" 한 줄.
2. **차는 검증용, 개발은 rosbag으로.** 하루 첫 30분은 녹화(기존 계획 그대로), 이후 B·C는 각자 노트북에서 재생하며 개발. 시간표 예: 오전 A, 오후 B, 저녁 C처럼 블록을 미리 정합니다.
3. **노트북끼리 ROS 간섭 방지:** 각자 노트북의 `ROS_DOMAIN_ID`를 차량과 **다른 번호**로 둡니다(예: 차량 30, A 31, B 32, C 33). 같은 공유기에서 bag 재생 토픽이 차량에 섞이는 사고를 막습니다.
4. **차량에서 코드 수정 금지, 파라미터만.** 차량에서 바꾼 값은 `tune/` 브랜치로 커밋 → 노트북에서 기능 브랜치에 반영. 스크립트가 미커밋 변경이 있으면 배포를 멈춥니다.
5. **조종기 든 사람 = 그 시간 차 사용자.** 원격으로 노드를 띄우는 사람과 차 옆 사람이 다르면 반드시 음성으로 "출발"을 주고받습니다.

## 7. rosbag 녹화와 가져오기

```bash
tmux new -s bag
bash ~/axel_ws/src/autorace_bringup/scripts/record_bag.sh lap_slow      # Ctrl+C로 종료
```
- 저장 형식은 `.mcap` 권장: `ros2 bag record -s mcap ...` (Foxglove/Lichtblick이 Windows에서 바로 열고, ROS 없이도 재생). 현재 `record_bag.sh`는 기본값(sqlite3)이므로 `-s mcap` 추가를 권합니다 **(Humble에 `ros-humble-rosbag2-storage-mcap` 설치 필요)**.
- 노트북으로 가져오기: `scp -r limo:~/bags/20261105_* D:\도균\AutoRace\bags\` (대용량은 유선 또는 5 GHz에서).
- 압축 이미지 토픽만 녹화하므로 1분에 수십~100 MB 수준 **(추정)**. 1단계 `df -h` 결과로 하루 녹화량을 정합니다.
- 공유: Git이 아니라 팀 공유 드라이브(구글 드라이브 등). 파일 이름에 날짜·조명·배터리 상태를 넣습니다.
